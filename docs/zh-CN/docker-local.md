# Docker 本地分发

[English](../en/docker-local.md) | [简体中文](docker-local.md)

维护的 Docker 分发包含网页构建、后端依赖和独立 Python 工作镜像，明确选择 Docker；隔离不可用时不退回本机无限制执行。原生 Windows 启动器仍默认使用 MXC。

## 启动与停止

安装 Docker Desktop，或 Docker Engine 25+ 与 Compose v2。选择 Linux 容器并保留默认 seccomp。先启动 Docker，再在下载的仓库目录执行其中一条：

```powershell
.\scripts\start-docker.cmd
```

```sh
sh scripts/start-docker.sh
```

脚本检查引擎、构建固定版本镜像并等待应用可用。打开 [127.0.0.1:8765](http://127.0.0.1:8765)。构建会下载公开依赖；启动不自动打开浏览器、下载行情或调用模型。

Windows 入口适用于 Windows PowerShell 5.1、PowerShell 7 和命令提示符，也支持包含空格的路径。它仅在子进程内允许运行随附的 PowerShell 脚本，不会永久修改系统执行策略；组织强制的策略仍可能需要管理员处理。请只运行你信任的下载副本。

Windows 使用 `.\scripts\start-docker.cmd stop` 停止；POSIX 使用 `sh scripts/start-docker.sh stop`。将 `stop` 改为 `restart` 即可重启；更新时再次运行普通启动命令。这些操作不删除数据卷。除非确实要删除保存数据，否则不要使用 `docker compose down -v`。

Compose 命名卷 `lab-data` 保存项目、回执、生成结果和行情源。也可在启动前将 `LAB_DATA_PATH` 设置为自己明确选择、Docker 可访问的绝对目录。此设置只选择存储位置，不迁移或改写原有原生数据。后端 `LAB_DATA_ROOT` 将运行数据与只读源码分离。备份前先停止应用，再备份完整数据卷；回执可能包含私人方法和供应商内容。

## 凭据与首次历史运行

在**模型设置**中创建自己的连接。容器／非 Windows 会话只在后端内存保存密钥，不建立明文密钥库。重启后，在原连接上选择**重新填写密钥**：模型、价格、项目分工及历史请求保留。活动连接不能更换密钥，保存或续填都不会调用模型。环境凭据须明确选择；维护的 Compose 默认不传入供应商密钥。仅支持的 Windows 环境提供 DPAPI 持久保存，Linux 控制器不提供此能力。

确认并构建方法后，打开**运行与结果**，选定标的／日期并点击**准备数据**。该动作明确访问固定 Yahoo 日线端点，包含构建要求的预热历史，保留校验快照，不推理、不插值、不获取任意 URL。每次最多 100 个目录标的、1,200 个自然日内的 756 个交易日、两路并发、每标的一次请求，单响应最大 4 MB。失败标的单独显示；供应商修订或日期不可用可能阻止运行。准备后再设置现金／费用并开始历史运行，方法需要执行模型时另行授权费用。

## 信任边界与限制

可信控制器挂载 Docker socket，因此拥有 Docker 主机控制权。只在本机运行经过检查的应用源码；这不是公共托管服务，也不防御恶意控制器。不使用特权 Docker-in-Docker。生成代码与材料解析均在独立工作容器运行，不在控制器内执行。

任务以 UID/GID 10001 运行，无网络／端口、移除全部 Linux capabilities、启用 no-new-privileges 与默认 seccomp。根文件系统只读，限制一个 CPU、256 MiB 内存且无额外交换、64 个进程、输出和总时长。构建使用 16 MiB／512 inode 工作 tmpfs 和 8 MiB 临时区；临时区保留 noexec，固定版本 SDK 的路径校验通过只读系统 shell 执行已核验的脚本内容，不执行任务可修改的辅助文件。工作容器不获得源码仓库、个人目录、密钥、数据库、登录或 Docker socket。

单次 Docker 构建最多允许 50 次模型请求和 100 次工具操作，总时长 480 秒。这些是上限，不保证一定用满：剩余预算、上下文大小等限制可能让任务提前结束。一次“模型往返”指一次请求和回复；读取文件、修改和测试可能需要多次往返。原生 MXC 构建另有 16 次请求上限。

原生与 Docker 构建的原始请求、规范化后的供应商请求，均允许最多 **2 MiB（2,097,152 字节）**。这是传输／资源限制，不是模型 token 容量或注入防护。请求不会为了用满上限而填充内容；实际内容和剩余授权预算仍有效。调用前在配置 token 单价和受支持的长上下文档位计价基础上加 1.5 倍预留余量。已完成用量计价不乘该系数，并采用配置或受支持的缓存价格；用量／价格不全则保留预留。预算占用、用量计价与供应商账单是不同概念：当前未接入供应商账单，旧记录保持原样。参见[费用核算](materials.md)。原生 `gpt-6-luna` 使用官方上下文容量，约 200,000 tokens 时开始本地历史压缩；未知原生模型在容量核实前保留较小的回退配置。Docker 已有保存代码恢复，但自动本轮上下文压缩尚未实现。这些设置不保证任意长构建都能完成。

再次发起构建时，会把符合条件的已保存代码作为尚未验证的起点：失败尝试必须属于同一已批准方法版本；已完成构建可以用于修改出新版本。构建助手应先检查、修复已有代码，而非重新生成整个项目。失败代码只在安全可收集时保存；超时或资源撤销可能导致无法恢复。同版本失败尝试若已有完整代码，会先独立验证；通过则建立新的验证完成记录，不调用模型。原失败、批准和费用记录保持不变，不自动恢复付费请求。

历史决策仅通过任务专属 tmpfs 卷接收当前截止日的代码和输入，评估器挂载为真正的**只读**。可信种子容器保持该卷存活，直到评估结束；种子容器不执行生成代码。使用前检查容器／卷实际配置。仅收集有界、允许类型的普通文件，拒绝链接、设备及越界路径。删除任务不影响已收集结果；启动清理只处理本安装标记的未结束资源。模型请求先预留预算，响应先落盘再解释，禁用追踪和自动重试，未知费用继续保留。

原生 MXC 构建也限制产物遍历，并在进程树运行时监控工作区文件数量／大小。原生监控在两次检查之间可能超限，**不是**硬文件系统配额。Docker 配额边界已在下列 Windows Docker 环境检查；其他安装环境仍需验收。

## 验证矩阵与排查

| 环境 | 证据 |
| --- | --- |
| Windows 原生 MXC | 已有实际构建／评估检查；仍为原生默认 |
| Windows Docker Desktop，Linux/amd64 镜像 | Engine 29.9.3／Compose 5.7.0：已检查部分工作容器隔离／资源／清理、真实模型构建、代码恢复、独立测试及看图历史执行；重建后的完整后台镜像也通过了全新数据卷启动、材料解析、合成历史执行、脚本化 SDK 工具及重启／续填密钥检查 |
| Linux／macOS Docker | 提供分发文件，但尚未完成平台验收；Dockerfile 不等于支持证明 |

工作容器已通过 tmpfs 配额、只读挂载、有界输出、超时／取消和 SDK shell／补丁操作的部分真实引擎检查。自动化 SDK 测试采用脚本化响应，不进行模型推理；另行授权的真实验收已使用模型生成的杯柄代码、独立方法检查、看图历史判断及版本化仓位修改。完整后台镜像也已通过独立工作容器完成这些脚本化工具操作及纯代码合成历史案例，不使用作者凭据或宿主源码／数据挂载。重建后台容器后，项目、材料标识、运行结果和模型角色绑定保持不变；会话密钥按预期需要重新填写。空白数据卷后台还完成了两个随附案例的独立复制、重新绑定资料后的方法确认、独立工作容器中的起始代码验证，以及重启后项目哈希不变检查；没有调用模型或使用作者数据库。这些检查不代表完整安全审计或 Linux／macOS 平台验收。

**引擎不可用：** 启动 Linux 容器模式，完成所需系统重启。页面**隔离运行环境**只说明引擎／镜像就绪，不代表安全审计。**缺少镜像：** 运行维护的启动命令。**端口占用：** 停止占用 8765 的应用，或只修改 Compose 中绑定本机的主机端口。**重启后无密钥：** 在原连接续填，不必删除连接。**准备数据失败：** 检查交易日期和供应商可用性，不覆盖已有损坏／部分保存的源。**任务中断：** 保留证据和预算预留，不自动恢复任务或付费请求。不要通过放宽隔离或给工作容器挂载整个数据卷绕过报错。
