# 生成项目执行接口

[English](../en/execution-contract.md) | [简体中文](execution-contract.md)

## strategy-v1

标准库 Python 项目必须声明 `execution.json`，实现 `strategy.py:decide(context)`。构建时在隔离环境中验证清单及两个平台独立选定的合成输入。生成测试和接口检查不能证明全部方法语义正确，仍需复核方法专属案例。缺少可执行的入场、退出、仓位或模型标准时，必须澄清，不得补入平台交易默认值。

所有字段必填，拒绝额外字段：

```json
{
  "schema": "strategy-v1",
  "entrypoint": "strategy.py:decide",
  "warmup_bars": 20,
  "history_bars": 21,
  "responsibilities": {"code": "已确认的入场、退出及整数股数规则", "model": null},
  "judgment": null
}
```

数字仅示范格式，不是推荐规则。`warmup_bars` 为 0–500 个历史交易日；`history_bars` 为含当前日的 1–501 根可见行情，必须大于预热数。值由项目方法决定。初期仅支持已安装并验证的美股与 ETF 目录，不自动下载，不支持任意标的。

`context` 包含 `schema`、`cutoff`（YYYY-MM-DD 收盘）、`bars`（标的 → 有序 date/open/high/low/close/volume）、`account`（cash、equity、positions：标的 → 整数股数）、`state`（上次策略状态）、`previous_orders`（上一决策提交的订单在下一开盘执行后的结果）。订单包含 id、decision_id、signal_date、symbol、action、quantity、status、reason、explanation；成交另含 date、price、fee、gross。这些是观察数据，不能授权策略修改账户。隔离进程无法获得未来行情、完整历史文件、其他项目、主机文件、凭据或网络。

`decide` 精确返回：

```json
{
  "proposals": [{
    "symbol": "SPY", "action": "buy",
    "explanation": "已确认规则编号及满足条件的原因",
    "sizing": {"shares": 3}, "judgment": null
  }],
  "state": {"SPY": {"signal_anchor": 100.25}}
}
```

股数和锚点也仅是格式示范。可返回空建议列表。action 为 buy/sell/hold；买卖必须正整数股，hold 必须零股。每标的最多一条建议，保留列表次序。说明为 1–2,000 字符。先检查仓位和现金，再按需调用模型，成交时按实际开盘价再次检查。跳空导致资金不足时整笔取消，不擅自缩减仓位。不能超持仓卖出。最早下个交易日开盘成交；金额及费用按十进制四舍五入到美分。期末不自动平仓，末日订单保持未成交。手续费是明确运行假设，不是止损止盈规则。

state 为最大 16 KB、深度八层的 JSON 对象，可保存入场锚点、计数等方法状态；应对照 previous_orders 与实际持仓确认成交后再使用。状态无账户或文件修改权限，随结果保存。总输出只能一个 JSON 对象，最大 64 KB；禁止额外标准输出日志、NaN、重复键。历史决策目录为只读，执行前即拒绝新建文件及修改源文件／输入；构建仍在独立可写范围内进行。禁止安装依赖或文件持久化，跨日信息使用 state。

## 可选模型判断

### 可选账户管理规则

已确认方法需要按风险决定仓位时，执行清单可增加 `account`，必须完整提供：`mode: "risk-managed"`、`risk_fraction`、`max_weight`、`max_positions`、`entry_gap_limit`、`commission`、`slippage`、`progress_units`、`stagnation_sessions`、`trailing_stop_units`。这些值属于用户方法，不是平台默认交易规则；运行费用必须与已确认佣金一致。不提供该规则时，原有固定股数行为不变。

此模式的买入建议使用 `sizing: {"shares": 0}`、数值 `priority`（大值优先，同值按标的排序），以及按优先级排列的 `candidates`（1–10 个）。每个候选包含唯一 `candidate_id`、正数 `stop`／`target`／`volatility_unit`、当前可见区间内的命名 ISO 日期 `dates` 和有大小边界的 JSON `facts`。要求止损 < 当前收盘 < 目标价。公共账户按已确认风险、最大权重和含佣金／允许跳空的资金占用计算整数股，在后续机会前预留现金；策略不能填写账户余额或成交价。

执行顺序为：此前订单在次日开盘按滑点成交；收盘检查止损、目标、追踪止损和无进展退出；再处理按优先级排列的新入场。持仓和待买订单占用名额；入场价越过跳空／止损／目标边界时取消，不擅自改仓位。无进展退出统计未达到 `progress_units × volatility_unit` 涨幅的连续交易日，不是到期强制卖出。退出有独立可追溯决策编号，最后一天的退出保持未成交。输入账户另含 `available_cash`、`position_details`。此模式的显式卖出必须整仓退出；需要部分退出时使用固定股数模式。模型不能修改候选结构或账户规则。

仅当方法需要模型时，填写 responsibilities.model，并将 judgment 设为：

```json
{
  "criteria": "已确认的项目专属判断标准，明确通过与否及证据要求",
  "trigger": "方法何时请求判断",
  "tools": ["read_bars", "price_facts"],
  "uncertainty": "skip",
  "input_mode": "text_only"
}
```

对应建议的 judgment 为 1–2,000 字符的判断请求；null 表示该建议纯代码执行。触发条件必须来自已确认方法。uncertainty 为 skip 或 stop。代码拥有仓位与退出规则，除非方法明确要求模型判断退出；hold 不能调用模型。

`input_mode` 默认 `text_only`，与旧版本兼容。仅当已确认方法需要视觉判断时使用 `chart_and_text`。可信控制器只从已限定截止时点的可见历史中取建议标的最近最多 120 根行情，绘制 1024 × 640、不含元数据的 RGB PNG（`ohlcv-v1` 渲染、`rgb-png-v1` 规范化），包含线性原始 OHLC 蜡烛图、成交量、覆盖日期和实际截至日期。渲染省略的更早可见行情数量写入元数据；数值历史仍受原有文字／工具上限约束。不使用特定形态标记、生成代码提供的图片字节、上传示例、外部网址／路径、未来行情或范围外基准数据。纯程序和纯文本判断继续可用；旧确认文件及结果不迁移、不改写。

图表像素与文字只发送给独立指定的执行模型，前提是所选模型已启用图片且本次费用明确授权。与构建澄清共用[图片策略及保守预留](materials.md#视觉解释与模型选择)。能力／计费不受支持、图片无效、预算不足或取消会停止请求，而不是变成交易拒绝。每次请求记录图片策略、数量、尺寸和摘要。运行证据保存实际准备／发送的 PNG，以及来源日期、截止时点、数据哈希和渲染范围；本机私有目录中每次运行最多 1,000 张图、合计 512 MiB，每张规范化图片最多 512,000 字节。读取必须匹配已保存决策与摘要，不接受任意路径。保存了图片不代表失败／取消的请求一定已送达供应商，请结合请求状态检查。

决策检查器在判断／交易证据旁显示图表。浏览不调用模型；引用到对话时包含图表身份及渲染来源，并明确省略像素，不隐式附加图片。独立的审核示范导出器只允许包含与决策／来源元数据匹配的 PNG，不导出任意运行文件。随附案例已经使用该导出路径；新增导出仍须单独检查内容及权利。

模型严格返回 `{verdict, reason, evidence}`：verdict 为 pass、fail、insufficient_evidence；reason 为 1–3,000 字符；evidence 为 1–20 个 `{symbol,date}` 引用且必须存在于可见行情。有效否决、证据不足、缺失证据、输出错误、基础设施故障分别记录；错误停止运行并保留费用，不伪装为不交易，不自动重试。

仅允许 read_bars、price_facts。参数精确为 symbol、start_date、end_date；必须在当前可见区间，最多 120 根。后者返回首末收盘、最高最低及平均成交量。没有文件、联网或任意计算工具。简单判断最多一轮两次工具调用，然后一次最终回答，共两次请求，每请求最多 1,500 输出令牌。每次历史运行在项目预算内最多允许 1,000 次模型请求。历史工具限制无法消除模型训练记忆中的未来信息。

风险管理候选可配置 `judgment.rubric`：1–5 个判断项，每项为 `{description, start_anchor, end_anchor}`，锚点名称对应候选的 `dates`。模型必须按候选 ID 和判断项完整返回 `{"assessments": {"candidate-id": {"criterion": {"verdict", "reason", "evidence"}}}}`，证据日期必须位于该项固定区间内。程序聚合结果：任何一项失败则失败；否则任何一项证据不足则证据不足；其余通过。`review_nonpass: true` 对所有未通过候选进行一次条件复核，即使另一个候选已经通过。最终选择原排序中第一个通过者；复核不能改动锚点或强迫通过。

`repair_once: true` 允许对已保存但格式／证据不合格的候选回答修正一次，不会重试结果未知的网络请求。初判、复核各最多三次请求，包含一轮工具和一次格式修正，每请求最多 4,096 输出令牌；记录保留阶段和无效回答。只向模型提供候选标的截至当时的行情。可选 `judgment.history_bars` 单独限定模型可见历史（1–501 根且不超过顶层计算历史），同时约束文字、工具和图片。例如顶层 `history_bars: 170`、`warmup_bars: 169`，判断配置 `{history_bars: 160, chart_history: "declared"}`，程序计算得到 170 根，模型与图表只得到最近 160 根；这是支持的配置，不是方法矛盾。未设置判断历史覆盖值时，`chart_history: "declared"` 绘制完整顶层历史。每个候选有程序绘制、带固定日期标记的 `ohlcv-v2` 图表。默认保留旧 120 根 `ohlcv-v1` 行为。候选判断最多 10 张图、8 MiB 请求，仍需选定模型的图片许可和费用核算。每运行最多保存 1,000 张图／512 MiB；旧图表身份不变。

只有包含模型判断的清单才要求已保存的执行模型及单独费用授权，绝不借用构建模型。所有请求共用对话、构建使用的项目累计预算；成功原始响应先私下保存再验证，计费不明保留预留。取消在下一决策或请求前停止；已发出的请求可能完成并收费。重启标为中断，不自动恢复消费。

## 来源与限制

新运行必须选取关联确认版本、完成且带校验哈希的构建。旧构建仍可查看，但需重新构建取得接口。方法、文件、清单、市场快照、模型参数、运行假设全部冻结并哈希；篡改阻止运行。完整行情只留可信存储，每日新隔离目录仅收到截止切片。原生 Windows 默认 MXC，维护的 Compose 启动方式选择 Docker 工作容器；隔离不可用时两者均拒绝执行。实际验收环境见[运行验证矩阵](docker-local.md#验证矩阵与排查)。

容量：最多 100 个目录内标的、756 个决策日、每项目 100 次运行、冻结输入 16 MiB、组合记录 160 MiB。超过 10 个标的或 100 个交易日的运行，保存指向冻结行情的无损截止引用，不再每天重复存储整个滚动窗口，结果证据上限为 128 MiB。较小运行保留完整内联输入及 12 MB 结果上限。查看时只还原该决策当时可见的区间，并校验原始输入哈希与冻结行情身份；旧运行仍可读取。

每隔离调用允许 8 MiB 截止输入、20 秒及 64 KB 捕获输出，沿用进程树内存边界。每天开始前为允许的输入、建议、模型／工具证据及终止检查点预留空间；不足时在当日成交或请求前停止，取消待执行订单，保留已完成证据和费用。文件输出通过只读隔离阻止。附加主机检查／清理最多 512 项、深度八层、8 MiB 截止输入另加 2.5 MB 其他文件（每个最多 1.5 MB），每阶段两秒；异常目录保留，不进行无边界递归遍历或删除。

检查器按标的展示全部已保存输入，每页 40 根行情；已确认判断标准、状态、已知成交及完整模型工具参数／结果可展开，每页 12,000 字符。引用附带经校验的同项目运行／决策编号，不接受浏览器伪造证据。在用户另行授权发送对话后，可信后端解析实际保存的输入、仓位／成交／状态、模型依据、确认方法／清单及 Python 源码节选；交接最多 80 KB，明确标注 JSON／源码截取及省略行情。构建助手不得声称检查过省略内容或修改原运行。引用不自动发送，也不借用执行授权。结果独立存储，普通项目轮询不重复传输全部证据。历史行情采用已披露的冻结拆股调整、不再投股息口径；不属于实盘交易或收益承诺。
