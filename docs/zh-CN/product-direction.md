# 产品范围

[English](../en/product-direction.md) | [简体中文](product-direction.md)

## 用途

Strategy Agent Lab 帮助个人用户把投资方法变成可运行、可检查、可修改的策略项目。构建助手是产品核心；生成的策略程序及可选执行智能体是交付物。产品帮助实现用户的方法，不替用户寻找或保证盈利策略。

应用结合领域工作台与成熟编码运行时。公共基础负责权限、账户计算、模型访问和依据记录；生成项目提供方法专属规则与实现。杯柄是案例，不是通用接口的边界。

## 已有工作流程

1. 通过对话描述方法，附上相关资料或图表案例。
2. 澄清模糊规则、依据、例外与不可得数据；区分助手假设和用户陈述。
3. 确认不可覆盖的方法版本，包括仓位、成本、退出及模型判断规则。
4. 在隔离任务环境中生成并测试 Python 实现，检查文件和验证报告。
5. 使用冻结的日频历史数据运行兼容项目，查看决策、图表、交易、持仓和权益。
6. 将某次结果引用回同一项目对话，确认修改，产生新实现和运行，不覆盖原结果。

对话、资料、方法、实现、历史结果和版本属于同一项目。模型请求记录是辅助明细，不能代替交易结果。对话跟随用户语言或明确偏好，与界面语言独立。

## 角色与权限

| 角色 | 职责 |
| --- | --- |
| 用户 | 定义并确认投资方法、重要修改与模型费用授权 |
| 构建助手 | 澄清方法、引用来源、提出实现、生成代码与受约束判断流程、测试和解释 |
| 可选执行智能体 | 根据已确认标准评估允许读取的当时证据，返回结构化判断 |
| 应用程序 | 强制管理凭据、文件／网络权限、模型／资源限制、不可变身份和账户计算 |

可以完全计算的方法不需要执行模型。预期收益不佳本身不构成拒绝实现的理由；语义矛盾、关键规则缺失、数据不可得或能力不支持时，应说明并澄清。修复违背已确认方法的代码，与修改方法本身是两件事。

普通项目对话不能修改平台代码、取消权限或费用控制、安装任意服务，或直接改变账户余额。导入资料和工具返回是证据，不是扩大权限的指令。

## 当前能力与限制

- 持久化项目、真实模型澄清、不可覆盖的确认版本与版本化 Python 构建。
- 构建／执行模型独立配置；搜索模型目录与手动输入并存。目录存在不保证对话、图片或编码兼容性。
- 可追溯的文字、Markdown、CSV、文字型 PDF 与 PNG/JPEG 导入。构建对话可把规范化图片发给明确开启图片能力的模型；编码阶段收到已确认解释和不可变引用，不直接接收原图像素。
- 标准库 Python 与公共 [strategy-v1 执行约定](execution-contract.md)，初始支持经过验证的美股／ETF 目录、日频、现货只做多。兼容生成项目可提出受约束模型判断并使用带日期的图表和证据。
- Docker 后台与独立受限工作容器；另有原生 Windows MXC 执行路径。编码连接为 OpenAI Responses，其他适配器不因此自动具备编码兼容性。
- 上下文／请求／轮次／运行时间限制及保存源码后的继续修复。恢复保留以前的失败与费用，不等于无限记忆或保证构建完成。

资料采用直接读取与来源引用，没有独立向量数据库／RAG 服务、扫描件 OCR 或复杂版面提取。不提供实盘券商连接、托管多用户后台、任意依赖安装或自主策略寻优。详见[资料](materials.md)、[运行边界](docker-local.md)及[安全限制](security.md)。

## 同一产品，两种形态

**本地应用：**下载后启动 Docker，配置自己的凭据，处理自己的项目。不分发作者密钥、账户额度或私人数据库。启动、测试和浏览保存示范不得调用模型；模型访问与费用授权分别检查。

随附案例可以复制成独立、尚未确认的本地项目，包含资料节选和起始文件。用户配置自己的模型、确认方法并重新构建后才能运行。来源记录保持不变，不复制授权或历史结果。见[从案例继续](getting-started.md#从随附案例继续)。

**静态展示：**无需后台的只读查看器，与本地示范共用组件。访客可查看真实对话、确认规则、生成文件、测试、修改版本、历史结果和媒体，不能发起新对话或计算。明确标识保存回放，不放密钥表单或假装可用的实时按钮。

[只读工作台](https://xxiao053.github.io/strategy-agent-lab/)由 GitHub Pages 托管，[源码已公开](https://github.com/xxiao053/strategy-agent-lab)。相对资源与 hash 导航支持子路径和刷新。预览无需仓库网址；发布构建需要批准后的 HTTPS 仓库网址。构建新版本不会自动公开，部署仍是独立且需要批准的操作。

## 示例与证据

主要构建示范使用原杯柄完整配置：40 个标的，2024-01-02 至 2026-11-10 的 718 个交易日。包含基于资料的真实澄清、确认、代码生成与历史执行。独立核验覆盖选定的方法案例、数据截止和全部运行账目，不把原有专用运行器的结果改称为新构建结果。

较小 NVDA 案例保留中文 100 股改为 50 股的修改，分别保存确认版本和运行。原始专用杯柄示范保持不变。少量非杯柄测试检查公共接口，不把平台固定成杯柄模板。

可分发包包含整理过的真实记录与派生图，不含凭据、原始供应商请求记录或完整行情源。两个项目统一列在“我的项目”；已有原生项目打开真实编辑器，静态记录只读。`docs/media/` 提供工作台截图、修改 GIF 和字幕视频。视频浏览已有成果，不宣称新发起了实时构建。详见[示范说明](demonstration.md)。

生成项目自测、独立核验与历史模拟是不同证据，都不保证所有输入下的方法一致性或未来收益。范围、失败、不确定性与真实限制应明确保留。

## 分发与发布条件

Windows 原生与 Windows Docker 分别有分项验收证据。Linux/macOS 尚未实际验收；提供 Docker 定义不等于已支持所有平台。开发者提供依赖／镜像定义、启动入口、持久化与任务权限；使用者安装运行环境并配置自己的模型访问。

公开版保留有效源码／测试、准确的双语说明、真实审核示范和来源声明。私人计划、原始日志、数据库、过时方案与开发流水账放在仓库外。每个页面都应让首次下载产品的人看懂，不依赖开发对话。

发布前须完成[安全与内容检查](development.md#安全与发布门槛)、最终候选检查、软件许可证／署名及数据／媒体权限核对，并在公开仓库或网站前取得明确批准。安全边界由代码执行，开发过程中持续测试；任何审查都不能保证零提示注入或隔离绕过风险。
