# 开始使用

[English](../en/getting-started.md) | [简体中文](getting-started.md)

首页是构建工作台。“我的项目”列出本地项目、随附的完整杯柄与 NVDA 案例。无需凭据即可查看示范，也可以新建自己的项目并连接模型。

## 安装与启动

评估可移植分发时可使用维护的 [Docker 分发](docker-local.md)，由镜像提供依赖与隔离工作环境；请先阅读其明确的验证矩阵。以下原生 Windows 路径仍默认 MXC。

需要 Python 3.11+、Node.js 20.19+ 或 22.12+、pnpm。在项目根目录打开 PowerShell：

```powershell
.\bootstrap.ps1
.\start.ps1
```

安装脚本创建 Python 环境、安装依赖并构建网页。启动脚本在后台运行，只监听 [127.0.0.1:8765](http://127.0.0.1:8765)。两条命令都不会调用模型。网页右上方可以切换中文与英文。

新下载的仓库包含经过审核的完整杯柄构建项目和 NVDA 修改案例，可查看对话、方法、生成文件、测试与历史结果。已有原生项目打开真实编辑器；随附记录只读。原始杯柄执行[结果快照](../../examples/cup-handle/result.json)保留独立侧栏入口。它们均不依赖作者的数据库。

## 从随附案例继续

在本地应用打开随附项目，选择**方法版本**，再点击**创建可编辑副本**。新项目包含尚未确认的草稿、资料节选和起始代码。原始对话、确认、测试及历史结果仍属于原项目，可以从副本的来源链接查看，不会变成副本的新结果。

配置自己的模型分工，检查并确认草稿，再**构建并验证**。构建助手把起始代码作为不可信的编辑输入，按你确认的方法验证新实现。历史运行需准备自己的行情，并单独授权模型判断。复制本身不调用模型，不继承凭据、费用授权或成功构建状态；节选也不重建原图片文件。静态展示只读，不提供复制操作。

## 构建自己的项目

1. 打开**模型设置**，选择供应商并填写自己的 API Key，再**读取模型目录**，搜索并选择模型。目录失败时也可手动填写**模型 ID**。填写连接名称和当前 token 单价并保存。可选 Windows 本机保护，重启后仍可使用；会话保存则只保持到后端重启。
2. **检查连接**重新读取已保存连接的目录，不产生推理。目录不保证访问权限或任务质量；请选用支持所需输入和构建流程的模型。
3. **新建项目**，先贴笔记或讲一个不完整的方法。助手主动追问关键缺口并维护草稿。
4. 选择项目的**构建模型**，可按需要设置可选**执行模型**，再点击**保存模型分工**。未保存的修改会阻止模型任务，保存后需重新授权费用；纯程序方法无需执行模型。设置项目累计预算并授权调用，解决重要问题后**确认当前方法**。
5. 环境支持时点击**构建并验证**，在**实现与验证**查看生成文件、独立重跑的测试及明确标注的合成示例。**模型调用记录**保留请求与费用，不是交易结果。下载文件不包含凭据。
6. 对话提出修改，确认新草稿并构建新版本，旧版本与结果保留。

原生 Windows 构建需要支持 [MXC 的 Windows 11](https://learn.chatgpt.com/docs/windows/windows-sandbox#mxc-compatibility)、已安装的 [Codex CLI](https://learn.chatgpt.com/docs/codex-cli) 和 OpenAI Responses 模型。维护的 Docker 启动方式改用独立工作容器与 OpenAI Agents SDK，见 [Docker 配置](docker-local.md)。两条路径均使用页面选择的 API 连接，不借用个人 Codex 登录；隔离不可用时在编码推理前停止。生成项目使用 Python 标准库；构建检查采用合成输入，历史模拟则是下方单独、明确发起的步骤。

## 运行生成项目

构建前可在项目**材料**页导入笔记、数值或判断参考，检查原始位置并引用选定原文到对话。导入／预览不调用模型，发送消息须另行授权。原文随方法确认冻结，并交给两种编码后端。见[材料与限制](materials.md)。

完成带执行接口的构建后，打开**运行与结果**，选择构建、支持的标的、已有数据覆盖的交易日、初始现金及单边手续费。缺少或不足的本地行情会明确阻止运行，绝不替换成合成价格。旧构建缺少 execution.json 或校验哈希时需重新构建，但仍可查看。

首次使用时，在同一面板点击**准备数据**，明确从固定行情供应商获取选定范围与所需预热数据，显示进度并保留已有快照，不调用模型。会话密钥重启后可通过原连接的**重新填写密钥**恢复，不必重新绑定项目角色。

仅包含模型判断的方法需要保存执行连接并勾选运行专属费用授权，与对话、构建共用预算；纯代码运行不调用模型。查看曲线、成交、持仓、全部输入标的、判断标准及工具结果。**引用到项目对话**附带经校验的证据引用，不自动发送；另行授权构建请求时，选定的输入／成交／状态／模型证据及源码节选才随请求发送，并明确说明上下文省略内容。可移除附件。复核纠正内容后另行授权构建模型。取消不抹除已完成证据或费用；重启标为中断，不自动续跑或消费。详见[执行接口与限制](execution-contract.md)。

## 可选：已有杯柄历史研究

从侧栏底部打开原始杯柄执行参考，使用已有杯柄运行器。其模型配置和行情输入与构建项目独立。

### 准备行情

当前实现使用冻结的 Yahoo 日线 OHLCV 快照。创建研究前先获取数据：

```powershell
.\.venv\Scripts\python.exe -m scripts.freeze_market --config examples/cup-handle/config.json
```

该命令下载示范标的及区间，包含策略需要的预热历史。它会访问行情供应商，不会产生模型调用费用。数据经过校验和检查并保存在被 Git 忽略的 `artifacts/` 中，不覆盖已有源文件。供应商后续修订数据时，新下载的快照不一定能精确复现旧结果。

其他区间可使用：

```powershell
.\.venv\Scripts\python.exe -m scripts.freeze_market --start 2024-01-02 --end 2025-12-31 --symbols AAPL MSFT QQQ
```

随后在工作台选择数据覆盖的标的及交易日。开源客户端的许可证不等于行情数据的再分发许可。

## 配置模型

仅在尚无 `.env` 时，使用 `.env.example` 创建本地配置。设置相应后端环境变量后重启本地服务。不要把密钥写入方法描述、浏览器存储或提交的文件中。

见[模型与预算](models.md)。配置好供应商不代表所选具体模型支持图片或工具。

## 运行与检查

1. 打开“新建研究”，编辑支持的方法、数值条件与判断标准。
2. 确认方法、标的、区间、账户及交易规则。
3. 执行机会预检；候选数不等于成交数。
4. 选择模型研究，确认能力、计价信息，并明确授权费用上限。纯程序运行可用于本地工程检查，但不作为产品示范。
5. 查看进度、判断、交易、持仓与模型记录。

多个标的共享账户。模型通过不保证成交，价格跳空或账户约束仍可能阻止买入。区间结束时按市价计算未平仓权益，不强行平仓。

## 暂停与回放

暂停在安全边界生效。成功响应先持久化再解释，继续运行时可以复用。通信结果未知时，供应商可能已经计费，必须明确确认后才能再次请求。回放使用版本匹配的已保存响应，不保证重新调用模型仍得到相同答案。
