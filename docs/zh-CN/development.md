# 开发说明

[English](../en/development.md) | [简体中文](development.md)

## 目录结构

```text
lab/                 后端、智能体流程与模拟账户
web/                 中英双语 React 工作台
scripts/             本地启动与行情获取
tests/               离线回归及可选集成测试
examples/cup-handle/ 经过检查的配置与衍生结果快照
examples/builder/    真实保存构建项目及经过审核的图表
docs/media/          实际截图、配字幕视频和修改 GIF
docs/en/             英文文档
docs/zh-CN/          一一对应的简体中文文档
```

运行目录（`runs/`、`artifacts/`、`logs/`）、虚拟环境、网页依赖／构建产物和密钥均被忽略。本地归档放在仓库外，不是构建软件的依赖。

Docker 分发输入为 `Dockerfile`、`Dockerfile.worker`、`compose.yaml` 与完整精确版本的 `requirements-runtime.lock`；`.dockerignore` 使用允许清单，排除本地数据、密钥与依赖目录。前端使用冻结的 pnpm 锁文件。边界与验收状态见 [Docker 本地分发](docker-local.md)。普通测试跳过引擎验收；启动 Linux 引擎并构建工作镜像后，明确设置 `LAB_DOCKER_ACCEPTANCE=1` 才运行 `tests/test_docker_engine_acceptance.py`。这些无模型调用的检查被跳过时不能报告为通过。

## 测试与构建

```powershell
.\.venv\Scripts\python.exe -m pytest -q
pnpm --dir web test
pnpm --dir web build
```

核心测试使用可控样例和模拟网络，不产生模型调用费用。标为 `market_data` 的测试需要私有冻结历史快照，缺少输入时会自动跳过。明确测试无私有数据的独立部分可执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q --without-market-data
```

不要静默下载行情来替换这类检查。它们验证固定源数据身份，属于可选集成证据，不是测试核心行为的前提。

前端开发：

```powershell
pnpm --dir web dev
```

Vite 开发服务会将 API 请求代理到 8765 端口上的本地后端。

## 安全修改

扩展产品时遵循[产品方向](product-direction.md)，区分构建与执行的职责和权限。不能只加聊天外壳，却把杯柄假设继续当成通用项目接口；不能为覆盖技术清单增加依赖。设计明确的策略边界，同时保留现有示范。

保留已冻结运行／配置／数据的身份信息，新规则进入新运行。测试仓位计算、日期截止、不完整模型输出、请求预算与响应复用。暂停或删除研究不能制造免费重试或抹掉已消耗的授权。

文档描述已实现的行为，不把未来计划当成现状。同步更新中英文。适配器样例测试不代表真实供应商兼容性已经验证。

## 分享边界

公开源码、测试、文档和经过检查的示范，与私有运行材料分开。公开推送前检查实际暂存文件中是否有密钥、通信记录、数据库和本机路径。确认软件许可证及必要的行情使用许可。不要为了方便排障而提交私有归档。

### 静态展示构建与验收

GitHub Pages 用于只读公开展示，不用于托管应用后端。独立静态入口与本地应用复用保存项目组件，只读取随包数据。两个构建示范与正式媒体均已打包；最终发布／内容权利验收及公开部署仍是独立条件。原始执行示范另有标识，不能算作新的构建产出。

无需发布配置即可构建本地预览：

```powershell
pnpm --dir web build:showcase-preview
```

用静态 HTTP 服务打开 `web/dist-showcase-preview/`。相对资源路径与哈希链接支持项目子路径、直接链接及刷新，不需要路由后端。两种模式共用“我的项目”及对话／成果工作台。仅当来源身份明确相同时，本地原生项目优先于可分发记录；同名但不同身份的项目仍分别保留。静态项目只读，不调用模型。未配置仓库时，预览不显示 GitHub 链接，但提供可用的本地运行说明。

正式构建命令 `pnpm --dir web build:showcase` 要求 `VITE_SHOWCASE_REPOSITORY` 是已批准的 HTTPS GitHub 仓库地址，并要求 `examples/builder/cup-complete/project.json` 已包含经过审核的完整构建示范。产物写入 `web/dist-showcase/`，不会上传。构建不等于批准发布。随包示范和图片文件名必须明确审核，添加时同步更新严格的 Docker 输入清单及前端构建阶段的复制路径。

发布展示构建前须检查：

随附的 **Review or publish static showcase** Actions 工作流只能手动触发，默认仅测试／构建并上传审核产物，不发布网站。完成下列检查并获所有者批准后，在仓库 Pages 设置中选择 GitHub Actions，再手动启用 **publish**。只有该部署任务具有 Pages 写入权限；源码链接取自实际仓库，不使用模型凭据。工作流已准备并接受本地策略测试，尚未在 GitHub 执行。文件采用 YAML 的严格子集 JSON。

- 没有凭据、运行数据库或本地后端时仍能读取已审核且可分发的示范；用没有应用缓存状态的全新浏览器验收。
- 在项目的 Pages 路径下验证导航、直达链接、刷新、资源及媒体；检查不请求本地 API 或模型供应商。
- 明确标识已保存的示范，不提供密钥表单或不可用的实时操作；源码与本地运行入口指向有效位置。
- 审查完整静态产物，包括示范数据、JavaScript、源码映射和媒体的隐私及分发权利。即使界面没有展示，静态资源也可被公开下载。
- 部署须在发布审查和明确批准之后；准备好构建或工作流不等于获准公开。

## 安全与发布门槛

本地分发不使用共享托管账户，但不会消除 Prompt 注入或宿主机安全风险。导入文档、粘贴笔记、参考代码和工具返回内容都可能夹带恶意指令。提示词与结构化响应只是辅助防护，权限、文件、网络和费用边界必须在模型之外强制执行。用户主动修改自己的源码，与正常安装被不可信材料操纵，是不同的情况。

功能开发时同步建设防护，发布前再开展明确范围的安全审查，覆盖：

- 密钥是否经接口响应、校验错误、日志、导出、环境继承、镜像层和构建缓存泄露。
- 聊天／材料／工具返回中的注入、未授权方法变更、伪造验证证据及读取未来历史信息。
- 路径穿越、链接、上传／解析器、脚本／HTML 展示、本地网页来源／Host 和未授权访问本地服务。
- 原生／容器隔离边界、挂载、网络／转发服务、Docker 控制接口暴露、依赖和运行时来源。
- 预算预留、未知计费、请求／循环／资源上限、中断、清理和恢复。

优先使用无敏感信息的探针和离线样例；真实安全探测须有明确范围及费用授权。报告测试版本／环境、可复现问题、修复与回归、未测试部分和剩余风险。已有单元测试或一次无命中的密钥扫描，不等于完整安全审计，也不保证零风险。

发布内容审查与运行安全审查分别进行。保留产品源码、有维护价值的自动化测试、当前中英文文档及经过清理且可分发的示范／媒体。排除私有计划／归档、过时文档、废弃代码、临时脚本、包括注释在内的内部开发流水账、参数搜索、废弃试跑、排障记录、原始供应商通信、数据库、凭据和无再分发许可的源数据。经过审核的真实产品构建对话可以是示范，开发平台时的内部聊天不是。将废弃材料移到仓库外归档前先核实依赖，不为包装删掉有用测试、许可证声明、用户项目或实际能力限制的证据。检查实际暂存文件、拟发布的全部历史、压缩包、静态网站产物、媒体、Docker 构建上下文和镜像层；`.gitignore` 不能保护所有导出路径。若真实凭据曾被公开，须撤销／轮换，不能只删除当前文件。

原创软件和文档采用 [MIT](../../LICENSE)，并保留[第三方声明](../../THIRD_PARTY_NOTICES.txt)。两种前端构建均输出这些声明与双语[数据说明](../../DATA_NOTICE.zh-CN.md)；Docker 同时在应用根目录和前端产物中保留它们。依赖变更时应更新准确的声明，检查打包后的许可文件，而不只检查元数据标签。数据／媒体再分发权利与软件许可分别核对，参见 [Pages 检查与发布](github-pages.md)。完成审查不自动授权推送、公开上传或发布镜像。详细私有审查记录留在公开仓库之外，面向用户准确说明安全限制。
