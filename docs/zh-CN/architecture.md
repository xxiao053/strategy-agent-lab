# 系统设计

[English](../en/architecture.md) | [简体中文](architecture.md)

## 目标产品与当前范围

产品是帮助用户把投资方法变成策略项目的构建智能体；执行智能体是项目可选的组成部分。通用构建已接入生成项目共享历史运行器；原杯柄案例保留独立且不改写的执行路径。见[产品方向](product-direction.md)。

原杯柄配置、判断字段、提示词、工具和执行器仍有策略专属性；共享执行使用独立的 strategy-v1 接口。固定杯柄区间、三项判断和数值优先流程不成为其他方法的要求。

## 项目构建

`workspace_store` 独立保存项目、对话、草稿、确认版本、请求费用和构建记录，不改写冻结的历史研究。`workspace_agent` 使用通用方法结构，新材料包含来源消息编号。确认操作保存不可变的方法版本。

`example_copy` 仅接受固定随附案例及选定的方法版本；先检查源码哈希、文件大小、可移植路径与引用，再原子创建未确认草稿。经过审核的资料节选具有新项目自己的 ID 与规范化哈希。副本不继承凭据、角色绑定、批准、回执、运行或执行校验标识。起始代码是不可信的正常构建输入，绝不由宿主导入执行；来源链接保留对未改变原案例的追溯。

`materials` 通过选定的隔离边界导入项目私有文字／Markdown、CSV、可提取文字的 PDF 与静态 PNG/JPEG 示例。原件和解析预览在 `LAB_DATA_ROOT` 下具有不可变 ID 与哈希；选定行／页／记录／图片引用有大小边界，随草稿修改保留并冻结进确认方法。授权澄清可向明确启用图片的模型发送规范化像素；代码构建收到确认的解释和不可变引用，不含原始图片像素。`build_runtime` 与 `sdk_builder` 均在独立验证前写入并校验明确标为不可信的 `MATERIAL-REFERENCES.json`，编码运行时不取得原始路径或材料库权限。见[材料流程与限制](materials.md)。

`connections` 管理用户明确选择的供应商和模型。会话凭据只存在内存，可选 Windows DPAPI 本机保护。检查连接仅读取目录，不证明模型已经能够推理。

项目提供 `model_roles: {builder: connection_id|null, execution: connection_id|null}`，旧项目读取为明确未设置。模型分工接口原子校验两个已保存连接，有活动任务时拒绝修改。对话与构建使用构建角色，可选历史判断只使用执行角色；新增请求保存角色／连接／模型快照。只有构建角色未设置时兼容旧版直接指定对话／构建连接；缺失绑定绝不回退。模型目录接口只需供应商与明确填写的密钥或环境授权，响应有大小边界、不创建连接。目录、结构化对话和通过验证的构建状态分别记录。

`build_runtime` 调用已安装的 Codex CLI，使用独立运行目录，不继承个人登录或上级说明文件；禁止项目外读取与写入，禁止命令联网，仅对运行时目录开放必要读取。模型调用前必须通过非敏感探针。真实 API Key 由后端转发层持有，每次请求前预留项目共享预算并保存响应事件，限制请求大小、输出 token 与请求次数；未知结果不自动重试。进程限制约束时长、输出和进程树内存，并清理子进程。

每次构建使用新目录，绑定已确认版本，保留代码、测试及合成结果。平台选择的测试／演示命令及独立 strategy-v1 输入输出检查均在隔离环境执行；篡改方法／接口文件或报告零项测试均不能通过。生成的测试代码可能虚报自身成功，因此其输出明确标为自测报告，不是独立核验。独立方法案例、源码完整性、数据截止与账户检查另行提供证据，也不证明所有输入下的策略正确性。构建可使用 Windows MXC／Codex CLI 或 Docker 工作容器／OpenAI Agents SDK，编码接口为 OpenAI Responses，产物使用 Python 标准库；带接口的成功构建获得冻结执行哈希，供历史运行使用。

符合条件的已保存代码可以作为后续构建起点，不必整套重新生成。同版本失败产物先独立验证；若已完整通过，则建立新的仅验证成功记录，不调用模型。否则，模型辅助修复仍受单独授权和限制约束。原失败和费用记录不变。原生构建支持有界的本地历史压缩；Docker 的保存源码恢复不包含自动本轮压缩。两条路径都仍可能达到请求、时长或预算上限。见[构建限制与恢复](docker-local.md)。

生成文件当前位于 `runs/builds/<项目编号>/<构建编号>/project/`，每次构建的运行环境另存于旁边的独立目录。这些本地输出被 Git 忽略，只有审核后的导出内容才能成为公开示范。本地保存不意味着获得授权的模型请求不包含项目上下文。

## 公共执行约定

`execution_contract` 验证 [strategy-v1 清单和决策接口](execution-contract.md)，包含历史要求、代码／模型职责、可选标准／工具／不确定处理、整数股建议及有大小边界的 JSON 策略状态。`project_evaluator` 使用选定的 MXC 或 Docker 边界，每日提供新的截止范围输入，绝不在主进程导入生成代码；隔离不可用时绝不回退主机。`project_account` 负责十进制美分现金、费用、只做多仓位与下一开盘成交，不捏造止损、止盈或期末平仓规则。

历史输入必须限定为判断时点可获得的信息，既包括价格，也包括文档。策略代码和工具不能读取完整未来数据。决策通过校验接口交给账户模拟器，不允许直接篡改余额或制造成交。正常“不交易”、证据不足、数据缺失和基础设施失败必须分别记录。

`project_runs` 冻结并哈希确认方法、文件、清单、已验证本地行情快照、模型参数和假设。独立 SQLite 表把有大小边界的完整结果与摘要轮询分开；重启标为中断，不自动续跑。`project_judgment` 在共享预算下提供最多一轮只读工具与一次最终回答，保存请求编号和收据。`ProjectRuns` 展示配置、进度、权益、成交、持仓及证据，并可引用到同项目对话。修改建立新版本／运行。初期仍限已验证美股／ETF 目录，不是任意数据导入；真实模型／运行环境验收与离线接口测试分别记录。

方法可选声明风险与账户管理规则，以及按优先级排列的固定入场候选。`project_managed` 复用已有账户算术，不调用策略专属筛选或历史运行器；未声明该规则时，固定股数行为不变。`project_assessments` 校验候选的命名判断项，可对每个未通过结果条件复核，按原排序选第一个最终通过者，不改几何。计算历史和模型可见历史可明确分别指定。较大运行使用冻结行情的无损截止引用，避免重复保存每个滚动窗口。接口支持最多 100 个目录标的和 756 个交易日，但这不等于某个生成实现已经忠实执行了已确认方法。

## Docker 后端与本地分发

明确选择的 Docker 后端在可信控制器使用 OpenAI Agents SDK 0.24.0，将受限命令／文件工具放入加固、无网络工作容器。历史决策使用复制的任务专属只读卷，不绑定控制器路径。`docker_policy`、`docker_runtime`、`sdk_budget`、`sdk_builder` 分别负责策略、生命周期、请求计费和 SDK 接入。启动、信任边界、配额及验证矩阵见 [Docker 本地分发](docker-local.md)。Windows 上已实际执行 Docker 构建及历史运行；原生 Windows 启动器仍默认 MXC，维护的 Compose 启动入口选择 Docker。

隔离执行作为可替换后端。Docker 是跨平台分发目标，已有 Windows 分项验收；MXC 仍为原生 Windows 默认方式，Linux／macOS 宿主机须另外验收。Docker 支持不只是把网页服务装进容器，编码、独立测试和策略运行也必须保持同样的权限边界。

维护者提供固定运行依赖、镜像／构建定义、启动配置、持久化映射、资源限制和升级检查。用户安装并启动兼容的 Docker 环境、提供自己的模型凭据，不需要自行设计容器权限。项目成果保存在宿主机或明确管理的存储中，不随临时容器销毁而消失。只挂载任务所需的可写内容和必要只读资源，不开放整台电脑或整个仓库。

生成工作负载不能获得宿主机供应商密钥、个人登录、特权容器模式或 Docker 控制接口。受控服务处理允许的外部请求并计入授权。验证目录外访问、网络限制、资源耗尽、子进程清理和重启行为。跨平台密钥保存与操作系统／CPU 兼容性须单独验证，不能凭 Dockerfile 宣布支持。模型费用授权不包含安装软件或启用系统虚拟化的授权。

## 已有杯柄执行工作流

**确认方法 → 冻结行情 → 筛选数值候选 → 检查账户可执行性 → 智能体判断 → 校验信号 → 模拟组合交易 → 查看过程。**

| 组成 | 职责 |
| --- | --- |
| 用户 | 提供并批准方法、判断标准和执行参数 |
| 策略引擎 | 指标、数值条件、固定形态区间与候选编号 |
| 智能体 | 对指定候选应用标准，按需调用限定的证据工具 |
| 账户引擎 | 现金、仓位计算、订单、成交、费用与退出 |
| 运行控制器 | 编排、预算约束、输出校验、持久化与恢复 |

这条历史运行流程接受可配置的杯柄方法。构建生成的项目走上方独立流程，不会被偷偷映射到杯柄运行器。

## 有边界的智能体执行

每次机会提供固定候选编号、数值事实、截至判断时点的行情与图表，以及精简参考资料。模型逐一判断杯体、柄部和连贯性，为每个候选返回通过、拒绝或证据不足。

工具可以查看允许的数据区间、计算候选指标或生成局部图表；不能读取未来行情、修改形态锚点、改变账户状态或联网搜索。每阶段最多一次工具往返和一次输出修复，总计最多三次请求。主判断未通过的项目可有条件复核，共享运行预算。

程序校验必填候选编号、判断汇总、证据日期和形态位置。技术失败使运行暂停，不会伪装成策略拒绝。

## 行情与交易执行

数据快照校验标的身份、校验和、交易日顺序与 OHLCV 一致性。历史判断只接收截至当时的信息；输入截止边界不代表消除了模型训练中可能记住的历史知识。

程序筛选后，先检查是否至少有一个候选可以买入，再发起新的模型请求。已有持仓、待成交订单和预留现金均计入检查。模型通过不能绕过仓位、现金或风险限制。

信号在收盘产生，最早于下一交易日开盘成交，计入配置的费用和跳空规则。卖出由程序决定，不由 LLM 决定。账户支持固定止损／目标及配置的未进展／跟踪退出，不按总持仓年龄无条件卖出。

## 持久化与恢复

SQLite 保存冻结配置、数据身份、账户断点和请求记录。成功响应先保存再解析。恢复时核对完整请求身份并复用已知响应，不自动重试计费结果未知的请求。

输出不完整的恢复需明确触发、绑定版本且有次数上限。删除研究记录不会清零已使用的共享预算，累计费用占用仍保留。选定示范只要求已完成的模型运行，不依赖数值对照。

## 技术实现

- Python、FastAPI、Pydantic、SQLite 和单个本地执行线程。
- React、TypeScript、Vite 构建中英双语工作台。
- 后端模型适配器，浏览器不保存密钥。
- 直接提供带来源的方法参考资料，不依赖向量数据库或 RAG。
- 不包含无边界的多智能体投票、分布式队列、券商连接或多用户认证。

本地服务拒绝非本机 Host 和跨来源请求；这些保护不能替代公开托管所需的独立安全设计。
供应商 JSON 响应在解析前限制为 32 MiB；原生构建流限制为总计 64 MiB、单事件行 8 MiB，不接受远端压缩。每次收到数据块时检查累计传输时限（240 秒），另有 120 秒的套接字空闲上限；正在阻塞的读取最多可再延续一个空闲时限。触及限制保留未知结果的预留，不自动重试。子进程输入与输出并行传输，输入管道塞满不会绕过监控超时。

SDK 异步响应路径用 240 秒取消期限包住发送／读取。模型目录与行情下载同样在读取前拒绝压缩，逐步累积数据，分别限制 1 MB／4 MB，并在数据块之间检查 30 秒累计时限；另有 20／10 秒空闲超时。这些元数据请求不是推理，不产生模型费用。
