# 安全与限制

[English](../en/security.md) | [简体中文](security.md)

## 适用环境

使用可信副本在本机单用户运行。应用不适合直接暴露到公网、由互不信任的多用户共用，或连接实盘券商。静态展示版是没有模型后台的独立只读产物。

Docker 后台持有 Docker 控制接口，因此具有 Docker 宿主机权限。它是可信应用代码，不防御恶意维护者或被攻陷的后台。生成程序与解析器在独立受限工作容器中运行，不获得该控制接口或模型凭据。不要给工作容器添加宿主目录、特权模式或网络访问。

## 程序强制执行的控制

- 本地 Host／Origin 校验及变更请求头保护浏览器接口，但不能防御已经以同一系统用户运行的恶意软件。
- 限制资料字节数、类型、解析输出和解析资源；检查项目引用、生成文件的身份、路径穿越与链接。导入文字／代码是不可信数据，不授权修改平台控制。
- 方法确认版本不可覆盖；构建和运行绑定方法、代码、数据与模型身份，修改进入新版本。
- 历史任务仅接收截至当时的输入；程序负责账户计算与决策校验，模型不能直接制造成交或更改余额。
- 生成任务不继承凭据、私人数据库、个人登录态或 Docker 管理权限；工作容器限制文件写入、CPU、内存、进程、时间、输出和网络。隔离检查失败时不降级为无保护执行。
- 模型请求须明确授权并在发送前预留额度；未知计费结果继续占用预留，不静默重试。启动与浏览保存示范不调用模型。
- 不可信文字和生成源码只作为内容展示，不在浏览器执行。示范资源在打包前明确选择并校验。

具体行为与边界见[系统设计](architecture.md)、[Docker](docker-local.md)、[资料](materials.md)和[模型／费用](models.md)。

## 剩余风险

提示词、结构化输出与容器都不能彻底消除 Prompt 注入。模型可能误解资料、遗漏规则、生成错误代码，或给出貌似有理却没有依据的解释。应检查确认规则并用独立案例核验。生成项目自测不是独立证明；独立示范核验也只覆盖已说明的案例。

数据截止边界阻止任务读取后来提供的行情，但不能消除模型训练中记住的未来信息。图表可能不展示更早的数值历史，界面披露可见日期和数量；模型应报告视觉证据不足，而不是声称看过未展示日期。

原生 Windows 工作目录监测是周期性检查，不是硬磁盘配额。Docker 隔离依赖宿主内核、Docker 运行时和可信后台；依赖／漏洞检查不能证明它们没有未知漏洞。Windows 验收不能认证 macOS 或 Linux 宿主机。

模型请求会把获准的项目上下文发送给所选供应商。即使密钥受到保护，本地响应记录、资料和数据库也可能包含私人内容，应妥善备份并保护完整数据位置。容器会话密钥只留在内存；原生 Windows 可选 DPAPI 保存。明确选择的环境文件由操作者管理，不是应用加密保险箱。

## 分享之前

检查实际文件、示范文字、图表、媒体、构建产物、镜像层和 Git 历史，不能只依赖忽略规则。未经许可不要分享私人数据库、原始模型通信、凭据或源数据。静态资源即使不显示在界面上，也能被下载。

公开网站仅提供静态项目记录和媒体；实时模型任务仍在本地应用中使用操作者自己的凭据运行。软件许可证／署名、数据／媒体权利和发布批准分别处理。若凭据泄露，须撤销它；删除文件不等于撤销访问权限或抹掉已发布历史。详细问题与测试依据保存在私有审计记录，本页不保证零风险。
