# Project materials

[English](materials.md) | [简体中文](../zh-CN/materials.md)

An editable copy of a shipped example contains **source excerpts**, not the author's original private files. Excerpts have fresh project-local IDs and hashes; copied method citations point to them. Image-only historical references are textual excerpts, not available image pixels. Upload your own images when a new visual interpretation is needed.

Open a project's **Materials** tab to import UTF-8 `.txt`, `.md`, `.csv`, text-extractable `.pdf`, or still PNG/JPEG screenshots and examples. Import, listing and preview do not call a model. Review original line (`L`), PDF page (`P`), CSV record (`R`) or image (`I1`) locations; CSV cells include column numbers (`C`) and literal headers. Dates, tickers and quantities are not automatically interpreted. Scanned/image-only PDFs explain that OCR is unsupported; encrypted or damaged PDFs must be re-exported. Complex PDF layout reconstruction is not supported.

Select locations and choose **Reference selected locations in chat**. This attaches immutable material IDs, SHA-256 hashes and selected text to your next separately authorized builder message. Explain the intended meaning and resolve ambiguities before approving. Rules retain conversation-message references alongside material citations. The assistant is instructed to explain its interpretation and ask about ambiguous semantics; citation validation cannot prove that every interpretation is correct.

Selected source text is retained in the method draft across revisions and frozen in each approved version. Importing another file, even with the same name, creates a new identity and cannot rewrite earlier versions. Construction receives a bounded `MATERIAL-REFERENCES.json` reference file containing the approved text and locations, explicitly marked untrusted. Both construction backends reject changes to protected approved inputs. Generated code receives no original paths or access to the material store. New material cannot override approvals, permissions, settings or system instructions.

Material-aware replies bind each rule through structured `material_refs` containing an exact material ID, SHA-256 hash, and inclusive `start`/`end` locations. Every unit must belong to the selected or already-retained source set; noncontiguous locations use separate ranges. Human-readable attribution can remain Chinese or English, without changing the method's rule text. Missing or inconsistent structured attribution is rejected before updating a draft; approval and construction recheck the same mapping. Legacy no-material replies keep their existing schema, and old saved versions are not rewritten. Attribution metadata has its own 24,000-byte bound in addition to the source-text bound.

## Bounds and privacy

- Up to 20 immutable files per project; text/PDF uploads are at most 512,000 bytes. PNG/JPEG originals are at most 2,000,000 bytes and 16,000,000 decoded pixels, one still frame only. SVG, GIF, animation, corruption, mismatched types and path-like filenames are rejected. Request bytes are bounded even without Content-Length; local Host, Origin and request-header checks remain required.
- Up to 100,000 extracted characters, 10,000 text lines, 100 PDF pages, or 1,000 CSV records and 50 columns. Preview paginates source locations. Select fewer locations or split long material if a location/context exceeds the limit; content is not silently truncated.
- Selected and retained method source context supports 128 KiB of UTF-8 JSON within a 2 MiB conversation-context cap. Complete numeric references and method notes can stay together; exceeding the bound requires selecting relevant source locations. This release has no vector database, automatic retrieval or material-removal workflow.
- Parsing uses stdlib CSV, pinned `pypdf==7.0.1` and `Pillow==13.0.0` inside the selected read-only, networkless execution boundary, never the controller's unrestricted process. One parse runs at a time without holding the global project mutation lock; project state is rechecked before attachment. Commands have a 20-second bound and bounded output (800,000 bytes); native process-tree memory is bounded at 2 GiB and Docker worker memory at 256 MiB. Isolation failure stops import with no host fallback. Temporary scopes are cleaned up; anomalous cleanup failures are reported, not hidden.
- Originals and parsed previews live under `LAB_DATA_ROOT/materials/<project UUID>/<material UUID>/`, or the local checkout's ignored `materials/` by default. Only generated paths are used. Integrity checks bind both original and parsed content. Local private files are not encrypted at rest by the application; protect your account and backups.
- Materials, approvals, construction references and saved artifacts are private local project data, not automatically published. The reviewed example exporter uses an explicit allowlist; every additional public export still needs separate content and redistribution-rights review. Authorized model requests do transmit selected/retained project context to your configured provider.

## Visual interpretation and model selection

For historical execution through OpenAI, if the coarse image reservation exceeds the remaining authorized budget, the controller may first use the official [input-token counting endpoint](https://developers.openai.com/api/docs/guides/token-counting). It sends the same approved input, images, schema and tools to the selected provider without generating a response. The refined reservation uses the returned count plus 25% and 1,024 input tokens of headroom, the full output cap and the existing rate multipliers. The budget itself does not increase. Counting failure, invalid counts or an unaffordable refined estimate stop before inference; no automatic retry or guessed lower fallback. Counts and reservation method are retained with the eventual request. Other providers and builder image clarification retain the coarse policy below.

The private original remains immutable. `rgb-png-v1` applies orientation, composites transparency on white, preserves aspect ratio without cropping, limits the longest edge to 1024 pixels and reencodes metadata-free RGB PNG, at most 512,000 bytes. Images that cannot fit are rejected with re-export advice rather than silently losing more detail. Preview shows the actual normalized image, original filename and normalized dimensions/hash before selection. Original and normalized identities are both retained; image previews are same-origin PNG responses with integrity checks, not caller-supplied paths or URLs.

At most **two distinct selected/retained images** belong to an active method. Successful clarification retains their identities and pixels for later authorized follow-ups; excess images fail explicitly. No OCR text, quotations or detected regions are fabricated. The builder receives real pixels and labeled sources, distinguishes observation, interpretation, confirmed rules and uncertainty, and asks about consequential unreadable/ambiguous details in the user's conversation language. Embedded image instructions cannot change permissions or budget. Review interpretations before approval.

Saved connections default to text-only/unknown image capability. In **Model settings**, explicitly enable images on an idle saved connection and confirm the selected model supports them and bills image inputs as tokens at the configured rate. This reuses the saved key and makes no inference. Currently only the OpenAI Responses, Anthropic and Gemini protocol adapters support the `token-v1` image billing profile; catalog presence or provider-wide capability is not proof for a model. Other adapters, per-image fees and custom billing profiles are blocked. A valid authorized image response may record transport/schema success, not guaranteed semantic understanding. Text responses never establish image capability. Capability changes and credential renewal have generation checks and cannot race active project/catalog tasks.

Image requests have an independent 1,600,000-byte wire ceiling; text-only prompt, source and construction bounds do not increase. Before dispatch, the input allowance is `text wire bytes + 8000 + sum(max(32768, encoded image bytes, normalized pixel count))`. The capped input/output allowance is priced at configured rates (using the highest configured input/cache rate for the input allowance), including an applicable supported tariff, then multiplied by **1.5 for reservation only**. The per-image 32,768-token floor covers known base/tile costs for tiny or skinny images that pixel/byte counts alone miss; it is not another model's image-token formula or a provable universal bound. When needed and supported, a bounded provider input-token count can replace the coarse allowance before inference.

After a response, reported input/output/cache token counts are priced at the saved configured rates **without the reservation multiplier**. The workbench separates this usage-priced amount, pending reservations, and legacy budget records. It has **no provider invoice integration**: actual billed cost is unavailable, not zero, and must be checked with the provider. Missing/incomplete usage, missing cache prices or unknown outcomes retain the reservation without automatic retry. Existing records are not repriced or relabeled as bills. Optional cache read/write rates can be supplied when creating a connection; blank is not a zero rate. For the exact OpenAI `gpt-6-luna` model, an omitted cache-read rate uses its standard 10% ratio relative to configured input price; cache-write prices require explicit configuration, and inputs above 272,000 tokens apply the documented 2× input/cache and 1.5× output tariff. These tariff adjustments are not a safety margin. Other models use the configured rates; custom/non-token billing is unsupported. No fast, priority or regional-premium service is implicitly requested. Request evidence saves price/policy snapshots and image identities without raw image payloads in project JSON.

Approved construction receives immutable image identity and the approved visual interpretation/rules in protected text/source views, never raw base64 pixels. The separate coding engine has **not** seen the original image. Historical visual execution uses separately rendered cutoff price charts, never these uploaded examples; see [Execution contract](execution-contract.md).

Windows MXC parsing has been exercised with harmless generated PDF and Unicode text fixtures. A real Docker image-decoder transport fixture has also passed with a metadata-heavy PNG, normalized identity and task cleanup. Offline fixtures do not establish live model semantics or cross-platform acceptance; those require separate verification. See [Docker verification status](docker-local.md).
